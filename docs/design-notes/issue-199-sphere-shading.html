Design note · Issue #199

Body shading, Sun halo & a palette nudge

Give every orbiting body a hard-edged lit and unlit half, put a soft halo behind the Sun, and shift the planet colours a step toward how they actually look — without losing legibility at 5–21 px on a dark card.

approved Issue: #199 Slices: 4 Area: src/renderer

Context

Bodies render as flat discs today: renderBody() in src/renderer/bodies.ts appends a single <circle fill={body.color}>. The scene already carries enough information to light them — the Sun is drawn at (CENTER, CENTER) every frame, so the direction to the light for any body at screen position (x, y) is just the vector (CENTER − x, CENTER − y). Issue #199 asks for three things that build on that:

  1. A visible day/night split on each body, lit half vs unlit half, divided by the diameter perpendicular to the Sun direction.
  2. An “energy flow” effect around the Sun — resolved here as a static radial glow, no animation.
  3. A palette revisit: the current hexes in planet-data.ts were picked purely for contrast on the dark slate theme, not for resemblance to the real planets.

The intended outcome is a scene that reads as lit by a central star rather than as a diagram of coloured dots, while every body stays identifiable at its real pixel size. No LESSONS.md exists in this repo yet, so there is no prior root cause or guardrail for this problem class to check against.

Design it twice: the half-disc mechanism

All three options produce the same picture. The question is where the geometry lives and how the Sun’s “no split” case is expressed.

A — two <path> half-discs, inline in renderBody

Compute theta = atan2(CENTER−y, CENTER−x), take the diameter endpoints at theta ± π/2, append two arc paths — one bulging sunward in body.color, one opposite in the darkened tone. The Sun falls back to a plain circle behind an if (dx === 0 && dy === 0).

Trade: best locality, zero new seam — but scene geometry now lives inside the drawing function, and “don’t split” is a coordinate check.

B — keep the circle, overlay a clipped dark circle via <clipPath>

Leave the existing <circle fill={body.color}> untouched. Add a half-plane <clipPath> to <defs> and append a second circle in the dark tone clipped to it. Mirrors the renderVisibilityCone() idiom in observer.ts exactly, and keeps the “appends a circle with fill” tests almost unchanged.

Trade: drags <defs> lifecycle and per-body id bookkeeping into renderBody, which is <defs>-free today. A “caller knows internals” leak bought to avoid some test churn.

C — A’s geometry, extracted to svg-utils.ts with an explicit light source ← recommended

// svg-utils.ts, next to polarOffset / polarFromFocus
export function sunwardHalfDiscPaths(
  x: number, y: number, r: number,
  lightFrom: { x: number; y: number } = { x: CENTER, y: CENTER },
): { litD: string; darkD: string } | null;
// returns null when (x, y) === lightFrom  -> caller draws a plain circle

Same two path strings as A, but the geometry sits with the rest of the screen-space geometry — the file whose docstrings already explain the eclipticViewDirection mirror. That is exactly where the note “this split is a screen-space delta, so it is exempt from the mirror” belongs. Pure, DOM-free, unit-testable. The Sun is handled as data (lightFrom equals its own centre → null), not a special-cased name. renderBody and renderCometBody both become thin callers; the Saturn slice reuses it for the shrunk body.

Verdict: C. A and C draw the identical result; C puts the geometry where the project already keeps screen-space math and turns “no split” into a value rather than a branch on the Sun’s name. B is rejected: the <defs>/id leak into renderBody costs more than the test edits it saves.

Why no eclipticViewDirection. Every point in the renderer that comes from an orbital angle must pass through polarOffset() so the ±1 ecliptic mirror is applied once and consistently (CLAUDE.md, #94). The half-disc diameter is not derived from an orbital angle — it comes from the screen-space vector between two already-placed points, (x, y) and (CENTER, CENTER). The Sun stays at CENTER in both views and the body is already mirror-placed, so the vector between them is correct in either view with no extra handling. The helper takes no direction enum by design.

Slices

Slice 1 — hard half-disc for planets & Moon  ACCEPTED

  • Add sunwardHalfDiscPaths() to svg-utils.ts + unit tests (endpoints on the circle, diameter ⊥ light vector, null when coincident).
  • renderBody(): when the helper returns paths, append the dark path then the lit path (lit on top); when it returns null, keep today’s single circle. Unlit tone via color-mix(in srgb, ${'{body.color}'} 35%, black).
  • Red test: bodies.test.ts — “appends a circle with fill body.color” becomes “appends a lit path in body.color and a dark path” for an off-centre body; the Sun-at-centre case still asserts a plain circle.
  • Untouched: positions[].color, offscreen markers, dynamic labels and the Saturn ring stroke keep reading flat body.color.

Shipped: helper returns { litD, darkD } | null; litD = arc(0) bulges sunward, darkD = arc(1) away; `d` form M x1 y1 A r r 0 0 {sweep} x2 y2 Z. renderBody draws dark then lit. Contract change (off-centre body: <circle> → two <path>) rippled to 6 pre-existing tests that located bodies by circle[fill=…]; fixed with a type-agnostic bodyPos() locator in index.test.ts and a snapshot regen. Reviewer: no correctness findings; /simplify hoisted the delta vector. 1210 tests green.

Slice 2 — same split on comet heads  ACCEPTED

  • renderCometBody() in comets.ts already computes the sunward unit vector for the tail; feed { sunX, sunY } as lightFrom to the same helper and replace the head <circle> with the two paths.
  • Tail rendering unchanged.
  • Red test: comets.test.ts — head is now a lit/dark path pair oriented away from the Sun.

Shipped: the dark-then-lit block from slice 1’s renderBody and this slice’s comet head was pulled up into one exported renderShadedDisc(svg, x, y, r, color, lightFrom?) in bodies.ts (/simplify during review) — renderBody and the comet head are now one call each. comets.ts imports it from bodies.js (no cycle; the dependency already existed for ORBIT_COLOR). Slice 3’s ring arcs are a different shape and deliberately do not use it. 1211 tests, 100% coverage.

Slice 3 — Saturn ring shadow arc

  • renderSaturnRings(): each ring is currently a full stroked <circle>. Split each into a lit arc <path> plus a darkened arc <path> on the anti-sunward side.
  • Shadow arc is approximate: centred on the anti-sunward direction, angular half-width atan2(bodyRadius, ringRadius) — the planet’s shadow cylinder as seen from ring distance. Not a true projected-ellipse shadow.
  • An arcPath(cx, cy, r, a0, a1) helper falls out here and is shared with Slice 1’s path building.
  • Red test: bodies.test.ts renderSaturnRings — two arcs per ring; the dark arc spans the anti-sunward sector.

Slice 4 — static Sun halo + palette nudge

  • Halo: a <radialGradient id="sun-halo"> in <defs> (gold at ~0.5 alpha → transparent) backing a <circle> of ~2.5–3× the Sun’s radius, drawn behind the Sun body. Reuses the <defs> insert pattern from observer.ts. No filter.
  • Palette: edit the eight hexes in planet-data.ts only. Values flow to markers, labels and rings for free.
  • Sign-off artefact: this note’s Preview doubles as the palette check — adjust the proposed values here until approved, then copy them into planet-data.ts.
  • Red test: index.test.ts — a halo circle is appended once, larger than and behind the Sun; palette values assert against the new constants.

Adjacent opportunities — filed separately, not folded in

  • Extract arcPath() and move renderVisibilityCone() onto it. Slices 1 and 3 both build arc path strings; the cone in observer.ts hand-assembles a similar path today. Worth a dedicated refactor once this lands. → new issue.
  • Bootstrap LESSONS.md. The shared harness expects a by-symptom lessons log at the repo root; this repo never created one. → chore issue.
  • Not pursued: the <radialGradient> + <defs> helper introduced for the halo could later back a comet-head glow or Moon earthshine. Noted, not built — #199 chose the hard half-disc, no soft light anywhere.
