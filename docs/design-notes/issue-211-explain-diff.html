Background

The card draws the solar system as one big SVG. Every planet is a small shape near a coordinate the astronomy code hands back, and two independent config switches decide how that shape looks:

  • display — "2d" draws each body as a flat filled circle; "3d" (the default) makes it read as a ball.
  • shading — true (the default) adds the astronomical day/night terminator: the side of the body facing away from the Sun is darkened. It also draws the Sun's halo and the shadow band across Saturn's rings.

These are deliberately orthogonal: you can have a flat disc with a day/night line, or a round ball without one. An earlier change (issue #199) tried hard to fake the “ball” look with an SVG radial gradient and never got it to stop reading as either a top-lit hotspot or a flat wash. The lesson recorded from that work: a translucent gradient cannot imply volume without also implying a light source and a direction. The fix was to stop faking it — pre-render a real Lambert-shaded sphere to a 128×128 PNG once (scripts/gen-sphere-sprites.mjs), inline it into the bundle as a data: URI, and blit it as an <image>. A per-colour <feColorMatrix> filter multiplies the grey sprite up to each body's hue. No <canvas> at runtime, which matters because the tests run under jsdom, which has none.

The wrinkle this PR fixes. #199 shipped two sprites. SPRITE_SOFT has viewer-weighted light and a high ambient floor — pure roundness, no direction. SPRITE_LIT has a hard in-plane light: a bright hemisphere and a dark one. With shading on, a 3D body used SPRITE_LIT, rotated by transform="rotate(sunBearing)" so its bright side faced the Sun — the sprite itself was the terminator. With shading off it fell back to SPRITE_SOFT. The problem: the hard hemisphere split of SPRITE_LIT reads flatter than the plain round ball. Turning shading on made a 3D planet look less three-dimensional, not more. Meanwhile 2D bodies already had a gentler treatment for the same concept — renderBodyShadow lays down an elliptical wash (terminatorShadowPath) over the away-from-Sun side, tinted by shadeFill to color-mix(colour 28%, black). Two mechanisms, one idea.

The idea

Collapse the two mechanisms into one. A 3D body stops swapping sprites: it always blits the round SPRITE_SOFT, and then — if shading is on — gets the exact same renderBodyShadow wash a 2D body gets, laid on top. Roundness comes from the sprite; the day/night comes from the overlay; they are now separate jobs done by separate code, for every body, in both modes.

The shape of every renderer becomes the same two steps:

draw the body form
sprite if display:3d,
else a flat circle
→
if shading and not the Sun:
renderBodyShadow(…)
one elliptical wash

Before, the day/night call lived inside the else branch (2D only); the 3D branch carried its own terminator via the rotated sprite. After, the call is hoisted out so both branches fall through to it. That is the whole behavioural change. Everything else in the diff is removing the now-unreachable machinery: the second sprite, the rotation, the bearing helper, and a parameter on renderBodyShadow that only existed to tell it “skip the core wash, the sprite already did it.”

A concrete body

Take Earth at screen (300, 250), Sun at the centre (400, 400), both switches on.

BeforeAfter
sprite <image>SPRITE_LIT, transform="rotate(56.31 300 250)"SPRITE_SOFT, no transform
day/night <path>none (sprite carried it)d = terminatorShadowPath(300, 250, r, 0.22) — byte-identical to what the 2D Earth emits

Across the whole fixed-date snapshot the counts move exactly as you'd predict: sprite rotate() transforms 10 → 0, and color-mix day/night washes gain one per off-centre body.

Saturn and comets

Saturn's core is just another body form — it takes the soft sprite and the wash like everyone else now. Its ring band (the shadow reaching out across the rings) is still drawn on top when shading is on, masked so it doesn't double-darken the core. Comet heads follow the identical pattern. The Sun itself is untouched: it sits at the centre, terminatorShadowPath returns null there, and it stays a flat disc — it is a light source, not a lit ball, and its halo carries its depth.

The code

Five source files, split across two commits — the behaviour change, then the cleanup.

src/renderer/bodies.ts — the core of it

renderBody is restructured to the two-step shape: draw the sprite (shade.sphere && !atCenter) or a flat <circle>, then a single if (shade.dayNight && !atCenter) renderBodyShadow(…) that both branches share. renderSaturn gets the same treatment for its core, and its ring-band renderBodyShadow call now passes an unconditional wash instead of suppressing the core.

Then the deletions. SPRITE_LIT (the constant) is gone. renderSphereSprite loses its sunDeg parameter and the line if (sunDeg !== null) attrs.transform = `rotate(…)` — it now unconditionally blits SPRITE_SOFT. sunBearing() — the helper that computed the screen-space angle from a body to the Sun — is deleted; it had no other callers. renderBodyShadow loses its coreShaded parameter and the if (!coreShaded) guard around the core wash; every caller already passed false, so the wash is now always appended.

src/renderer/comets.ts

The comet head is restructured to the same two-step shape, and the now-unused sunBearing import is dropped.

scripts/gen-sphere-sprites.mjs

The lit sprite generation is removed — the const, its log line, and the /tmp/sprite-lit.b64 write. SPRITE_SOFT was the only remaining caller of the internal sprite() function and always passed lo=0, hi=1, so that lo/hi smoothstep band is inlined away. This is algebraically identity for those values ((diff - 0) / (1 - 0) is diff; the hi - lo < 0.9 smoothstep never fired), so re-running the script still emits the byte-identical SPRITE_SOFT — verified during review.

src/types.ts, src/renderer/index.ts, src/card/card-config.ts

Comment-only. The ShadeOptions doc-comments still described sphere as “a radial gradient centred on the disc” and dayNight as having “a distinct straight edge” — wording that predates the Lambert sprite entirely. Rewritten to describe the actual mechanism. Two more stale “gradient” / “centred highlight” references in index.ts and card-config.ts were caught by the review's /simplify pass.

Tests

Six renderer/card tests that pinned the old behaviour (rotate() transforms, SPRITE_LIT vs SPRITE_SOFT, “no path over the sprite”) were migrated to assert the new contract; the two that only tested sunBearing and the sprite swap were deleted. The full-SVG snapshot was regenerated. One new one-line guard was added: "sunBearing" in bodies is false — a cheap lock against the export creeping back. Coverage stays at 100%.
