Issue #243 · Design note

Vendor the shared tooling, drop ha-card-shared

approved

ha-card-shared is a GitHub-tarball npm dependency carrying three unrelated things — four reusable CI workflows, a build/lint/test config baseline, and (it turns out) almost no runtime code. Its version lives in two places that don't know about each other — package.json and every workflow's @v2.1.0 pin — and that split is the actual source of the upgrade friction. Delete the dependency, vendor what this card really uses, and get new-card consistency from a GitHub template repo instead of a shared package.

#243 2026-09-11 1 slice

Problem

Every upgrade pain point traces back to the same structural mistake: treating a set of conventions as an installable package.

  • Two uncoordinated version pins. package.json's devDependencies/allowScripts pin github:marcintk/ha-card-shared#v2.1.0; every .github/workflows/*.yml separately pins the reusable-workflow ref @v2.1.0. Bumping one silently leaves the other stale — there is no mechanism that keeps them in sync.
  • npm ci fails against a git-tarball dependency in the sandbox harness (read-only npm cache).
  • GitHub-tarball packages aren't a tracked ecosystem for Dependabot's npm updates, so the package.json side never gets a bump PR at all — only the workflow refs, on the github-actions side, do. Two trackers, one logical version, no coordination between them.
  • Any shared-file change needs a build-and-republish round trip in a second repo before it reaches this one.

None of that is inherent to sharing conventions across cards. It's inherent to sharing them as an npm package.

Decisions

Five forks came out of the migration once the shared workflows' actual content was in hand. All five went through brainstorm-it before design; one went against the recommendation.

ForkChosenWhy
migration-check.yml Delete Its only job is tracking ha-card-shared recipe bumps — the premise disappears with the dependency.
validate-tag action Inline as steps One consumer, no reuse to justify a separate composite-action file.
actions/checkout, actions/setup-node Normalize to @v7 Matches deploy-demo-page.yml (already @v7); satisfies the issue's own "pin to current major versions" task.
Slicing One slice Human call, against the staged-slices recommendation — config, CI, dependency removal and docs land together.
CLAUDE.md / template toggle CLAUDE.md in-slice; toggle manual CLAUDE.md is a normal file edit. The GitHub "Template repository" checkbox is a Settings UI action — code-it cannot flip it.

Already shipped: the biome $schema fix

While investigating, the same drift pattern turned up inside a single file. biome.json's $schema was hardcoded to 2.4.6; the shared config it extends declared 2.5.12; the installed binary was 2.5.11. Three numbers, three sources of truth, silently disagreeing. 

  "$schema": "https://biomejs.dev/schemas/2.4.6/schema.json",
  "$schema": "./node_modules/@biomejs/biome/configuration_schema.json",

Pointing at the schema Biome installs alongside itself removes the drift permanently rather than fixing today's mismatch — the pointer can't fall behind because it is whatever's installed, no version number to remember. Applied already (uncommitted); folded into this slice rather than its own commit.

Plan

One slice. Acceptance: npm run check:ci, npm test and npm run build:prod all green with no ha-card-shared anywhere in node_modules.

  • Inline rollup.config.mjs, vitest.config.mjs, biome.json, tsconfig.json, prettier config.
  • Vendor src/globals.d.ts and test/test-utils.ts.
  • Inline the three surviving CI workflows at @v7; delete migration-check.yml; inline validate-tag's two steps into publish-release.yml.
  • Remove ha-card-shared from package.json and regenerate package-lock.json.
  • Fold in the biome $schema fix above.
  • Update CLAUDE.md — fold in the relevant CLAUDE-SHARED.md content, drop the include and the "promote to ha-card-shared" note.

Shipped

The plan landed as one slice, exactly as scoped, plus one thing the plan didn't anticipate. test/tooling.test.ts asserts none of package.json, biome.json, tsconfig.json, rollup.config.mjs, vitest.config.mjs, src/index.ts, or the three surviving workflow files reference ha-card-shared — red before the migration, green after, and it stays in the suite as the guardrail against the dependency creeping back.

Found mid-slice: a second, unrelated "skill lives in the wrong place" bug. CLAUDE.md described /show-it as a project-local skill (.claude/skills/show-it/, "not yet in the shared harness") — but the directory didn't exist on disk at all, and every other skill in .claude/skills/ is already a symlink into the external agent-harness repo, not a project-local file. Checked the harness: show-it was already there, just never symlinked in. Fixed by symlinking it (matching the other seven exactly) and correcting CLAUDE.md's claim. Not part of the ha-card-shared removal, but directly surfaced by running this slice's own review gate, and the same underlying policy applies: skills come from the harness, never from files committed in a card repo.

Adjacent opportunities

  • Enables, not folded in. Once workflows reference real actions/* pins instead of a reusable-workflow indirection, Dependabot's github-actions ecosystem tracks each action individually and correctly — the two-tracker gap this note opens with resolves as a side effect. The ha-card-shared-version-bump-gap memory entry can be retired once this ships.
  • Not folded in. Marking this repo as a GitHub template (Settings → General → "Template repository") and archiving ha-card-shared once no card references it are both manual, post-merge, human steps — listed in the issue, not performed by code-it.
  • Not folded in. Quality and security scanning (CodeQL, OpenSSF Scorecard, Socket.dev) is tracked separately as #244.

Trade-off accepted

Config drift across future cards becomes possible: a biome.json rule tweak no longer propagates automatically, it has to be copied by hand (or scripted) into each card. At a handful of rarely-changing pipelines, that's less lifetime cost than a versioned shared repo with two independent version pins that silently disagree.

Scope. This changes no card behavior — rendering, data sources, the solar-system view, none of it moves. Pure build/CI/config plumbing.
