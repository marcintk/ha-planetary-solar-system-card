Background

A GitHub Actions reusable workflow is one YAML file another workflow can call instead of copying its steps: a caller writes uses: owner/repo/.github/workflows/x.yml@ref and the logic runs as if it were written inline. It's a real feature, aimed at exactly this problem — several repositories that want the same CI. This card, and its siblings, called four of them from a separate repository named ha-card-shared.

A GitHub-tarball npm dependency is different from a normal npm package: instead of registry.npmjs.org, package.json points straight at a GitHub repo and commit — "ha-card-shared": "github:marcintk/ha-card-shared#v2.1.0". npm fetches and builds it like any tarball, but none of the registry machinery applies: no listing, no provenance, and critically, no Dependabot version tracking. ha-card-shared used this shape to hand out its build config, lint rules and test setup to every card that installed it.

So ha-card-shared was doing two things at once: supplying CI workflows by reference (a legitimate use of the feature), and supplying dev tooling by dependency (a much more fragile use of a mechanism meant for runtime libraries). This change keeps the idea — every card behaving the same way — and removes the mechanism that was quietly failing at it.

Why the version drifted

Picture two clocks meant to read the same time, wound by two different hands. That's what ha-card-shared's version became. Clock one: package.json's devDependencies entry, github:marcintk/ha-card-shared#v2.1.0. Clock two: the string @v2.1.0, retyped separately inside each of four .github/workflows/*.yml files, because a reusable-workflow reference is just a string in a YAML file — nothing links it back to the dependency declaration a few directories over.

package.json
devDependencies:
ha-card-shared@v2.1.0
↔
no link
↔
build-and-test.yml
uses: …@v2.1.0

Bump one clock — edit the dependency version — and the other four keep the old time. Nothing breaks loudly: the workflows still call a real ref, it's just the wrong one, one release behind. And because a git-tarball spec isn't an ecosystem Dependabot watches, package.json's clock mostly never got wound at all; only the github-actions ecosystem (which does watch uses: lines) ever opened a bump PR, drifting the two further apart with every cycle rather than closer.

The fix isn't a better synchronization mechanism between two clocks. It's one clock. Every file that used to say "ask ha-card-shared what the rule is" now just is the rule — there's no second copy anywhere to disagree with the first.

The change, file by file

Almost none of this touches src/ — the card's own logic imported zero runtime code from ha-card-shared, so the substance of this change lives in build config, CI, and docs instead.

  • rollup.config.mjs, vitest.config.mjs, biome.json, tsconfig.json — each used to import or extend a shared file inside node_modules/ha-card-shared. Now each carries that content directly: the bundle-name-pinning rollup config, the jsdom + 100%-coverage vitest config, the formatter/linter rules, the three base compiler options.
  • package.json — the ha-card-shared devDependency and its allowScripts entry are gone; the prettier key changed from a path into the removed package to an inline two-key object.
  • src/globals.d.ts (new) — the ambient __CARD_VERSION__ declaration and the window.customCards shape, copied in from the dependency; src/index.ts's one reference-path line now points at it locally instead of into node_modules.
  • The three surviving CI workflows — each uses: marcintk/ha-card-shared/.github/workflows/shared-*.yml@v2.1.0 line is replaced by the steps that reusable workflow actually ran (checkout, setup-node, install, build, test), with actions/checkout and actions/setup-node bumped from @v5 to @v7 to match what this repo's own demo-deploy workflow already used.
  • publish-release.yml also absorbed a second hop: it used to call a reusable workflow which itself called a small composite action (validate-tag) to check a release tag's shape. That action's two shell steps — detect pre-release, confirm the tag is newer than the last release — are now inline in this one file, since nothing else ever called them.
  • migration-check.yml (deleted) — its entire job was noticing when ha-card-shared shipped a version that needed manual migration steps. With the dependency gone, there is nothing left for it to watch.

Guardrail: test/tooling.test.ts reads each of the files above as plain text and asserts none of them contain the string ha-card-shared any more — it failed on all nine files before this change and passes on all nine after, and stays in the suite so the dependency can't quietly come back.
